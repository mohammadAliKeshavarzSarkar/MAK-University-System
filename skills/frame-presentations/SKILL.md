# FRAME — Presentation Architecture | Design & Production

## When to use

Use this workflow when planning, producing, revising, or reviewing an academic or technical **presentation**. It is a task guide, not an automatically installed ChatGPT feature.

## Read first

1. [Academic quality](../../standards/academic-quality.md).
2. [Source integrity](../../standards/source-integrity.md).
3. [FRAME Presentation Design Guidebook v0.2](../../design/frame-guidebook.md).

Follow the user's latest instructions and university rubric. Do not assume an unconfirmed font, logo variant, or chart color has already been approved.

## Production workflow

### 1. Brief and sources

Establish audience, topic, course, length, language, grading requirements, source materials, submission format, and presentation setting. Use information already available; ask only for essentials.

### 2. Narrative architecture

Build a clear slide outline before designing. Give each slide a purpose and a primary takeaway. For research: distinguish question, method, evidence, limitations, and conclusion. For technical topics: explain the mechanism, interfaces, and assumptions.

### 3. Visual architecture

Apply the MAK identity:
- Paper #F5F3EE, Ink #161616, and Signal #E64B3C as the documented **working content tokens**.
- Preserve the newer supplied geometric MAK logo artwork unchanged; the actual brand-image pixels differ slightly from these document tokens.
- Inter is the documented **working typography default**; PT Mono or IBM Plex Mono may be used sparingly for labels.
- Avoid substituting the exploratory Neue Haas Grotesk recommendation without confirmation.
- Prefer light slides for dense explanations; use dark slides only when contrast and the approved logo variant work.
- Use brand patterns selectively and only when they add value.

All detailed specifications and decision statuses live in the guidebook, not in this abbreviated file.

### 4. Production

Produce an editable 16:9 PowerPoint as the default when actual slides are requested. Use native text, shapes, connectors, and charts where practical. PDF is an additional delivery format **when requested**; speaker notes when useful or requested. If another medium is expressly requested, adapt rather than forcing PowerPoint.

Use technical diagrams, code, equations, charts, and citations appropriate to the content. Do not sacrifice readability to fit everything on one slide.

### 5. Quality assurance

Check:
- Accuracy against the provided and verified sources.
- Logical progression and actual teaching value.
- Correct labels, data units, legends, and source credits.
- Readability, contrast, image quality, RTL/LTR behavior, and font fallback.
- Visual consistency, image cropping, text overflow, and final file rendering.
- Editability and successful opening of the requested deliverables.

### 6. Learn from the pilot

Record what worked and what did not in the first sample or actual deck. Propose guidebook amendments separately and update version numbers only after review.

## Do not

- Redraw, invert, recolor, or distort the original MAK logo without approval.
- Copy an exploratory Canva layout as a mandatory presentation template.
- Invent metrics, citations, experiments, accomplishments, or affiliations.
- Use the résumé mockup as factual proof of university or career details.
- Publish private university course materials or personal data in this public repo.
- Pretend that reading this skill happens automatically in all AI environments.
