# MAK / FRAME — Design Learning Facilitator

**Status:** Reusable learning workflow, not a mandatory presentation template.  
**Created:** 2026-11-23  
**Scope:** Guided reading, critique, practice, and evidence-based design experiments.

## When to use

Use when the user asks to learn, continue a design lesson, compare visual alternatives, evaluate an example, or apply a design reference to university presentations. For a complete presentation deliverable, use the existing [FRAME production skill](../frame-presentations/SKILL.md); optionally consult relevant learning modules.

## Reading order

1. Read [source integrity](../../standards/source-integrity.md) and [academic quality](../../standards/academic-quality.md).
2. Check the [source catalog](SOURCES.md) and reopen the original page or the supplied book pages before making source-specific claims.
3. Choose only the module that fits the current question:
   - [Grid systems and composition](../design-grid-systems/SKILL.md)
   - [Typography and readability](../design-typography/SKILL.md)
   - [Visual hierarchy](../design-visual-hierarchy/SKILL.md)
   - [Visual rhythm across slides](../design-slide-rhythm/SKILL.md)
   - [Motion and choreography](../design-motion/SKILL.md)
4. For applied work, load the [FRAME guidebook](../../design/frame-guidebook.md) and use its confirmed brand choices without silently changing them.

## Data visualization as a parallel learning topic

For charts, plots, data encodings, and scientific communication, load [Data Visualization & Scientific Communication](../data-visualization/SKILL.md) and its own [five-source catalog](../data-visualization/SOURCES.md). These resources complement the visual-design modules but add numerical/data integrity obligations that aesthetics alone cannot satisfy.


## Four-step learning cycle

1. **Study:** Explain a small number of ideas from the actual source; preserve their context (poster, book, UI or presentation).
2. **Translate:** State explicitly which recommendations are original FRAME adaptations, not prescriptions by the source.
3. **Practice:** Change one design variable at a time using authentic or clearly labeled illustrative content. Preserve technical meaning and, where possible, produce editable examples.
4. **Review:** Compare readability, semantic correctness, flow, accessibility and limitations. Ask for the user's design judgment. Record findings as observations, not measured comprehension.

Do not automatically create a deck merely because an idea was mentioned. For a user's explicit exercise/build request, complete that deliverable. Favor a small meaningful experiment over a new framework.

## Evidence language

- **Source-supported:** Directly substantiated by a reopened, cited source.
- **FRAME adaptation:** Our reasoned transfer from print/UI design to slides.
- **Observed in pilot:** Actually inspected in our rendered examples; not audience research.
- **Open:** Requires user approval or further testing.
- **Approved production standard:** Only when established by the user and reflected in the relevant standards.

Never invent book pages, exact grid mandates, typography numbers attributed to a book, student learning outcomes, or motion timings said to be PowerPoint requirements.

## Current practical constraints

- MAK brand working colors: Paper #F5F3EE, Ink #161616, Signal #E64B3C; preserve actual official logo artwork.
- Inter is confirmed for Latin-script text; a Persian companion typeface remains unapproved.
- Lucide is the default general-purpose icon library, but custom icons and truthful diagrams are allowed.
- Examine final output in a real renderer; for Persian, check both text direction and physical ordering of token boxes.
- A repository skill is a document an agent must **explicitly load**; GitHub content does not automatically become ChatGPT instructions.

## Progress record

After an exercise, keep a concise record: objective, exact sources inspected, variable changed, deliverable, observed strengths/defects, what is still unverified, and whether any small standards change is worth a separate reviewable PR. No automatic promotion of experiments into universal rules.
