# FRAME / IMAGE — Generation and selective refinement

## Choose the correct production method

Use generation for a genuinely requested conceptual image or illustrative component. Retrieve unchanged authentic material for documentary needs; construct precise diagrams and data figures from source information. If a generation or editing capability is unavailable, say so; do not substitute a rendered mockup for editable content or report a nonexistent output.

## Prompt architecture

Specify as needed:

1. Purpose and placement in the slide.
2. Exact subject and intended meaning.
3. Medium (editorial 3D, graphic abstraction, etc.).
4. Composition, viewpoint, framing, focal position and text space.
5. Lighting and materials.
6. Art direction and color semantics.
7. Preserve/exclude constraints and non-evidential status.
8. Requested output ratio and background/transparency.

Example *new* brief, not the historical Pilot 01 prompt:

> Original conceptual illustration of modular software architecture. Matte charcoal geometric modules on a warm ivory background, one restrained vermilion accent, controlled directional studio light. Landscape composition with subject on the right and negative space on the left for editable slide text. No lettering, logos or invented technical labels. Metaphor only, not a literal architecture or measured evidence.

Inspect actual dimensions, visual output, factual meaning and suitability; the prompt is not proof of compliance.

## Reference-led editing

Provide the actual original asset and a narrow brief:

- **CHANGE:** the intended region or element.
- **PRESERVE:** geometry, proportions, viewpoint, focal position, lighting/materials and any meaningful details.
- **EXCLUDE:** new objects, invented labels, undesired effects or altered evidence.
- **OUTPUT:** actual placement/ratio and any needed transparency.

Save a separate candidate and compare with the original. If exact preservation is required, use deterministic editing or compositing and verify unchanged regions. A reference-led result can look faithful without having identical pixels. When comparing pixels, use matching dimensions and color representation, a documented region/mask and a stated metric; do not equate numerical differences with a validated perceptual measure.

## Actual pilot lessons

Pilot 01's exact generation prompt is unavailable; do not reconstruct it as historical fact. Pilot 02 requested an ivory support in place of red while preserving the original sculpture and setting. The visual change succeeded, but outside a declared rectangular region the images differed. A separate generation request yielded an infographic rather than the intended isolated modules and was rejected. The team used original deterministic SVG geometry instead. See [production QA](PRODUCTION-QA.md) for exact numbers and archive references.

## Records and approval

Retain originals and selected variants separately. Record actual tool/model if known, prompt and revision history, source references, file dimensions, checksums when useful, intended function, disclosure, rights review and reviewer status. Leave unknown details null rather than invent them. A rebuild using retained generated pixels is reproducible asset reuse, not deterministic image regeneration. Do not assume generated content is universally free of rights restrictions. Check the actual intended distribution and policy before approval.
