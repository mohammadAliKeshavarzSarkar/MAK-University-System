# Learn — Typography and Readability

**Status:** Learning skill. Brand typography decisions remain governed by the [FRAME guidebook](../../design/frame-guidebook.md).

## Core references

- [IBM Carbon — Typography](https://www.carbondesignsystem.com/building-blocks/foundations/typography/overview): IBM Plex, type tokens, scales, productive/expressive sets, weight and color as hierarchy tools.
- [Niggli — Grid Systems in Graphic Design](https://niggli.ch/en/products/rastersysteme-fur-die-visuelle-gestaltung): Publisher description of a book on applied grid systems; **not** access to all its typographic rules.
- [Poster House — The Swiss Grid](https://swissgrid.posterhouse.org/): Historical Swiss typographic context.
- See [catalog and limits](../design-learning/SOURCES.md).

**Do not adopt IBM Plex as MAK's primary font.** Inter is confirmed for English/Latin text; the Persian partner font is still open.

## Learning objectives

Understand how column width, font size, leading, weight and contrast influence line wrapping, scanning and content hierarchy. Recognize that a visually spacious slide may still contain a difficult concept.

## Exercise sequence

1. Select one authentic explanation; preserve its words, concepts and source credit.
2. Set an experimental 16:9 canvas and choose an underlying grid.
3. Compare one-, two- and three-column **spans**, changing the text block width while keeping the typeface and text content constant.
4. Compare realistic line-height variants, e.g. 1.0×, 1.3× and 1.6×. **These are FRAME exercise settings, not Müller-Brockmann or Carbon PowerPoint requirements.**
5. Evaluate line breaks, line tracking, text density, label hierarchy and space remaining for the technical visual.
6. Separately inspect English and Persian; confirm real glyph coverage, digits, punctuation, technical abbreviations and inline vectors in the exported slide.
7. Check actual renderer font substitutions and keep an explicit open issue when the presentation computer has not been tested.

## Comparison questions

- Are the headline, main explanation, secondary labels and citations distinguishable?
- Does an excessively narrow column fragment a sentence?
- Does an excessively wide column reduce readability or crowd the diagram?
- Is body copy neutral enough to read, with Signal red reserved for intentional emphasis?
- Are Latin mathematical arrays stable in RTL context? If not, isolate them in a separate editable LTR object.

## Outputs

A brief typography audit or two/three editable variants when requested, plus evidence of what was rendered. Record font names and unresolved portability. Do not promote tentative Persian font choices or exact grid/font-size ratios as official MAK rules.
